# 选题说明

## 项目名称与目标

**AgentCloud：面向有状态 AI Agent 的高密度复用与成本感知调度系统。** 项目研究如何在固定沙箱与内存预算下承载更多有状态 Agent，通过等待阶段的资源回收和按需恢复提高复用密度，并联合优化资源占用、切换成本与交互尾延迟。

## 目标用户与核心问题

目标用户是运行多个编程、研究或自动化 Agent 的平台开发者和运维人员。Agent 在工具执行、模型等待与交互间隙之间切换；每个会话持续保留执行环境会占用容量，频繁释放则增加快照与恢复开销。

核心问题包括：如何利用等待窗口复用热槽位；如何根据剩余等待和实测成本选择 KEEP / SUSPEND / RESUME；如何在高复用倍率下兼顾资源成本、任务完成率和首次准入等待。完整用户叙事见[产品故事](PRODUCT_STORY.md)。

## 复用基础与课程工作

| 技术组成 | 原项目基础 | 课程工作 |
| --- | --- | --- |
| 高密度有状态运行 | 64 个 Agent 共享 4 个 gVisor 热槽位；MEMORY 快照与恢复 | 复现容量配置，验证状态连续性，记录复用倍率与请求完成情况 |
| 等待与成本调度 | Observed、cost-aware、agentcloud-v2；条件等待估计和实测切换成本 | 分析决策路径，选择等待估计、释放时机或首次准入压力的改进点 |
| 容量与恢复 | Worker 容量观测、返回需求、恢复等待与生命周期互斥 | 分析首次准入及恢复排队对尾延迟的影响，验证容量安全 |
| 策略对照 | TTL2 / TTL15 基线、同机配对、统一反馈和 Program 生命周期 | 用相同负载与随机种子比较资源、尾延迟及控制开销 |
| 正确性与诊断 | 工具安全点、持久回执、Actor UID / epoch、指标与事件 | 验证重复请求、并发操作、恢复身份与故障处理，解释调度结果 |

## 研究问题

1. 在不同会话数、等待长度与工作集大小下，何时挂起能覆盖快照和恢复成本？
2. 等待样本不足或负载变化时，固定期限与条件成本策略分别表现如何？
3. 首次准入队列如何影响驻留决策，怎样兼顾高密度复用和排队公平性？
4. 调度收益中，资源释放、恢复频率和控制器观测开销分别贡献多少？

## 需求与验收标准

| ID | 优先级 | 需求 | 验收方式 |
| --- | --- | --- | --- |
| FR-01 | P0 | 在受限热槽位上运行更多有状态会话 | 固定槽位预算，记录会话数、峰值热槽位、复用倍率、计划与完成请求数；恢复后校验状态连续性 |
| FR-02 | P0 | 按等待与切换成本执行调度 | 记录输入观测、策略、成本、决策与实际动作；覆盖短等待、长等待、样本不足和返回需求到达 |
| FR-03 | P0 | 管理容量与恢复排队 | 验证容量约束和竞争处理，分别统计首次准入等待、恢复等待与交互延迟 |
| FR-04 | P0 | 提供可复现策略对照 | 同机、同负载、同种子比较固定 TTL 与成本感知策略，保存独立运行身份、原始数据和清理结果 |
| FR-05 | P1 | 解释调度收益与代价 | 图表和诊断关联驻留、挂起、恢复及排队事件，展示资源积分、尾延迟、恢复和存储开销 |
| NFR-01 | P0 | 保持状态与副作用一致性 | 校验 MEMORY 恢复、Actor UID / epoch、工具回执、安全点及重复操作行为 |
| NFR-02 | P0 | 联合评价资源与交互体验 | 报告总 Actor 预留 GB·s、交互 TTFT P95、请求完成率与有效吞吐；保留失败和缺测记录 |
| NFR-03 | P0 | 提供可复现交付 | 固定源码、依赖、配置、种子与测量窗口；执行回归验证并保存实验材料 |

原项目的 64 / 4 配置作为高密度复现目标，具体实验规模按设备条件记录。基础本地演示验证生命周期协议，MEMORY 复用与调度性能在真实 Substrate 和受控 Dynamo CPU Mocker 环境中测量。

课程策略对照计划采用至少三个完整种子对，资源与尾延迟使用逐种子配对差值和区间报告；引用原项目正式留出结果时保留其五种子协议。实验同时记录资源采样覆盖率、恢复次数、累计恢复耗时和首次准入等待。
