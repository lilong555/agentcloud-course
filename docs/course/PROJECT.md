# 选题说明

## 项目名称与目标

**AgentCloud：基于高密度复用与成本感知调度的个人 AI 云端工作台。**

面向大学生、科研人员和个人开发者，为写代码、处理数据、跑实验等任务提供独立云端工位。用户通过浏览器管理多个助手，等待时保存现场、按需休眠，需要继续时恢复工作。产品目标是减少环境重复配置与等待期间的资源开销，让个人在有限预算下使用多个有状态 AI 助手。

技术核心是**高密度复用与成本感知调度**：在固定热槽位和内存预算下承载更多会话，根据剩余等待、实测快照与恢复成本、容量压力选择 KEEP / SUSPEND / RESUME，联合评价资源消耗与交互体验。

## 目标用户与场景

学生可能同时维护课程代码、数据处理和图表任务；科研人员需要在多个实验工作区之间切换；个人开发者希望并行处理不同问题并保留各自环境。需求调研重点核实本地设备负担、离开后继续任务的困难、环境重建时间和云端预算。

个人工作台是主要产品入口，校园多人共享作为容量验证场景。完整使用故事见[产品故事](PRODUCT_STORY.md)，招募与访谈见[调研计划](RESEARCH_PLAN.md)。

## 轻量 Web 工作台

| 页面或操作 | 用户看到的内容 | 接入与验收重点 |
| --- | --- | --- |
| 我的工位 | 任务卡片、最近进度、工作 / 等待 / 存档 / 休眠 / 唤醒 / 排队状态 | 复用会话列表、详情、状态和事件接口，补齐任务名称等展示元数据 |
| 工位对话 | 用户指令、助手结果、工具运行状态 | 接入模型请求、结果认领与工具执行流程；刷新后按持久请求身份查询进度 |
| 文件工作区 | 文件列表、内容、恢复前后校验结果 | 复用 `file_read` / `file_write`，补齐目录列表与浏览接口；恢复后读取原文件 |
| 资源看板 | 工位总数、实际占用槽位、休眠数、恢复耗时、资源积分 | 按运行环境和时间窗口聚合指标，展示取数状态与比较基线 |
| 策略演示 | TTL 与 v2 的资源、交互等待和完成情况 | 启动或读取独立受控运行，同负载、同种子、同窗口比较，显示运行身份 |

前端根据服务端确认的状态展示进度；采样缺失显示“待采集”。“唤醒中”使用实际生命周期记录，“等待容量”使用恢复回执与排队观测。刷新、重复点击和网络恢复沿用原操作身份；结果未知时引导查看回执与工作区并完成对账。

## 资源与费用的展示口径

复用倍率为会话数 / 热槽位数，原项目 64 / 4 = 16×。工位总数、正在执行数和实际占用槽位分别展示，运行环境与采样时间随记录保存。

资源节省比例采用 `(基线资源积分 − 当前资源积分) / 基线资源积分`，比较相同配置、负载和测量窗口，基线积分须大于零。资源增量按实测数值保留。费用估算使用明确单价和计费单位，计算资源、模型调用、快照存储与 I/O 分项显示；采集完成的项目参与分项估算，完整费用在所有成本项具备依据后汇总。物理快照写入和峰值存储的现有缺测状态沿用[存储成本报告](../STORAGE_COSTS.md)。

交互 TTFT 从请求到达计至客户端观察到首 token，包含排队、恢复、准入与推理；恢复耗时单独统计。用户等待目标由访谈确定，并在实验开始前登记。界面文案采用实测值和已确认的状态。

## 调度研究与实验证据

课程选择一个主要问题开展实现和验证：等待样本不足时如何决定释放时机；恢复成本较高时如何减少切换；或首次准入队列如何参与驻留决策以改善排队体验。问题选择结合用户可接受等待和现有诊断结果。

原项目正式 Gate 2 采用真实 Substrate MEMORY 与 Dynamo CPU Mocker，N32 / N64、每规模五个留出种子、五种策略，完成 **50/50 trial、14,400/14,400 请求**。相对 TTL15 与 Observed，两种规模的资源与交互 P95 均达到联合改善；相对 TTL2，N64 的交互 P95 更高。这些数据用于确定研究问题与基线，个人用户体验另由真实试用记录评价。

课程配对实验计划采用至少三个完整种子对，报告逐种子资源与尾延迟差值及区间；引用原项目 Gate 2 时保留其五种子协议。固定会话数、槽位数、工作集、等待分布和测量窗口，记录请求完成率、恢复次数、累计恢复耗时、首次准入等待和采样覆盖率。

基础本地 `make demo` 使用确定性模型与 VOLUMES 文件恢复。MEMORY 连续性与高密度性能按[Substrate 部署](../../deploy/substrate/README.md)和[v2 实验协议](../V2_EVALUATION.md)验收。64 / 4 作为容量复现目标，实际配置随设备条件记录。校园试用记录真实参与人数、任务和使用反馈。
