# 选题说明

## 项目名称与目标

**AgentCloud：面向多智能体的有状态任务执行与资源调度平台。** 课程目标是让开发者通过清晰的任务界面查看 Agent 会话、操作暂停与恢复、理解工具执行结果，并复现一条完整的执行链路。

## 目标用户与问题

目标用户包括运行 AI 编程助手的开发者、需要复现任务过程的学生，以及演示系统运行状态的教师。一个任务通常包含模型等待、工具调用和多次交互，使用者需要了解当前进度、保存状态、恢复执行及定位失败原因。资源管理者还需要观察活跃会话和等待状态，安排有限的运行资源。

这些使用场景构成首轮调研假设。访谈将确认用户发生问题的具体频率、现有处理方式及最优先的操作入口。

## 复用基础与课程开发

| 项目组成 | 已有基础 | 课程开发目标 |
| --- | --- | --- |
| 会话管理 | 会话创建、列表、详情与状态 API | 会话列表、详情界面及状态刷新 |
| 暂停与恢复 | 检查点、挂起、恢复与 epoch 校验 | 操作入口、结果提示与冲突后的状态刷新 |
| 工具执行 | 工具 ID、持久回执和租户鉴权 | 回执查询、重复请求结果与错误诊断展示 |
| 事件与指标 | 事件查询、诊断及 Prometheus 接口 | 会话事件时间线与基础状态统计 |
| 演示与测试 | 本地演示脚本及 Go / Python 测试 | 面向课程的场景说明、界面验证与演示材料 |

源码依据：[API](../API.md)、[系统架构](../ARCHITECTURE.md)、[原项目说明](../../README.upstream.md)。

## 首轮需求与验收标准

以下条目为调研阶段候选需求，优先级在访谈后确认。

| ID | 优先级 | 需求 | 验收方式 |
| --- | --- | --- | --- |
| FR-01 | P0 | 查看当前租户的会话列表和详情 | 显示会话 ID、状态与执行代次；空列表、加载中和请求失败有清晰提示 |
| FR-02 | P0 | 暂停与恢复会话 | 操作成功后显示服务端状态；冲突响应触发状态刷新；重复提交沿用操作 ID |
| FR-03 | P0 | 查询工具执行结果 | 显示工具 ID、状态与回执；同一工具操作可追溯到同一结果 |
| FR-04 | P1 | 查看执行事件 | 按事件顺序展示会话变化；处理事件窗口过期并提示重新获取状态 |
| FR-05 | P1 | 运行课程演示场景 | 按 README 完成文件写入、检查点、暂停、恢复及内容校验，生成结果文件 |
| NFR-01 | P0 | 保持租户访问隔离 | 使用两个租户验证列表、详情与回执的可见范围 |
| NFR-02 | P0 | 保持操作与界面状态一致 | 模拟超时、重复点击和旧 epoch；依据服务端回执确认最终状态 |
| NFR-03 | P0 | 提供可复现的交付 | 新环境按文档运行；PR 通过 CI；保留命令、环境与测试结果 |

基础交付采用本地运行路径。进阶任务可接入 PostgreSQL、真实 Substrate 沙箱和 Dynamo，并记录各自的环境与测量条件。

## 课程协作与交付

团队按 4–5 人组建，角色可以兼任，职责见[团队分工](TEAM.md)。需求以 Issue 记录，开发使用独立分支，代码与文档通过 PR 合入。每项课程功能关联需求编号、验收结果和贡献者。

首课资料包括本选题、[资料调研报告](RESEARCH_REPORT.md)、[调研计划](RESEARCH_PLAN.md)以及[选题 Issue](https://github.com/lilong555/agentcloud-course/issues/1)。后续按教师发布的完整课程安排推进需求确认、设计、开发、测试和展示。
