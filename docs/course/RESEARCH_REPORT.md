# 需求调研报告

## 摘要

本轮资料调研聚焦有状态 Agent 的高密度资源复用与调度算法。AgentCloud 已提供 MEMORY 快照恢复、等待观测、成本决策和同机配对实验基础。课程围绕固定资源预算下的承载密度、资源成本与交互尾延迟开展复现和策略研究，用户访谈与问卷按[调研计划](RESEARCH_PLAN.md)采集。

## 用户与需求假设

**资源预算受限的 Agent 平台。** 平台需要承载多个长期保留状态的会话，关注同时存在的任务规模、活跃执行槽位和内存预算。调研将采集会话数、执行与等待时长、峰值需求和当前排队方式。

**成本与时延敏感的服务维护者。** 运维人员希望降低等待阶段的资源占用，同时保持可接受的任务返回延迟。调研重点包括资源计量方式、延迟目标、任务优先级及可接受的恢复开销。

**需要复现实验的开发与教学团队。** 团队需要在相同负载下解释策略差异，核对状态连续性与请求完成情况。调研将确认设备、实验时长、负载来源和结果展示需求。

## 算法与实验发现

现有调度器从已经发生的请求、闲置窗口和历史观测估计等待，使用实际快照、恢复及持久化耗时形成切换成本。v2 在样本支持充分时比较候选释放时刻与持续驻留的条件期望成本；样本不足时使用等待阶段的两秒期限，动作受安全点、驻留和稳定条件约束。

原项目正式 Gate 2 使用 N32 / N64、每规模五个留出种子与五种策略，完成 50/50 trial、14,400/14,400 请求。配对结果按负载和基线呈现资源与尾延迟的联合表现，提供固定 TTL 与成本感知策略的比较依据。

高恢复成本负载展示了明确的研究问题：保留热环境可以减少快照与恢复次数，同时延长其他任务的首次准入等待。现有 v2 的驻留成本纳入已登记的待恢复需求，规模 Runner 中尚未登记返回需求的首次 FIFO 排队由 Runner 管理；二者的衔接可作为课程的调度改进候选。

## 待验证问题与结论

首轮用户调研重点是会话规模、活跃比例、等待分布、资源预算、响应目标和任务优先级。样本编号、采集时间及匿名记录用于支持需求结论。

本项目以高密度有状态复用为产品目标，以成本感知调度为核心方法，以资源消耗、请求完成率与交互尾延迟为评价依据。课程可沿首次准入压力、等待估计或恢复成本选择具体问题，通过统一协议的配对实验检验实现效果。需求与验收条目见[选题说明](PROJECT.md)。
