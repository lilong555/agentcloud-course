# AgentCloud 软件需求规格说明书

版本：1.0。日期：2026-11-27。产品：个人 AI 云端工作台。适用阶段：软件工程课程设计，第 11 周需求基线。

**给每个任务一个云端 AI 工位，回来接着做。** 产品面向大学生、科研人员和个人开发者，在浏览器管理代码、数据和实验任务，依靠高密度复用与成本感知调度减少等待阶段的执行资源占用。

需求记录见[用户故事](USER_STORIES.md)，参与者和场景见[用例详述](USE_CASES.md)，对应关系见[需求追溯矩阵](TRACEABILITY.md)，依据见[证据索引](EVIDENCE.md)。本规格描述课程验收目标；每条故事标注已有技术基础和待交付部分，具体完成情况以关联 Issue 与验收记录为准。

## 一、功能需求

### 参与者与术语

| 对象 | 定义与职责 |
| --- | --- |
| 个人用户 | 学生、科研人员或个人开发者，主动创建工位、发起任务、查看文件并继续工作 |
| 课程演示者、测试成员 | 在独立演示环境执行策略对照、容量复现和交付核验；按授权查看该次运行数据 |
| 推理服务 | 次参与者，通过 Dynamo / 模型接口提供生成结果和请求状态 |
| 沙箱与快照服务 | 次参与者，通过 Substrate 提供工具执行环境、快照和恢复 |
| 工位 / 会话 | 一个任务的独立 workspace 及持久 session，携带文件、请求与操作历史 |
| 热槽位 | 同时承载执行环境的资源份额，多个会话按时间共享 |
| 安全点 | 关闭新工具准入、排空已准入工具并提交一致快照与回执水位的状态 |
| 恢复保真度 | MEMORY 保存可验证的进程状态；VOLUMES 演示验证文件恢复，界面据实标识 |
| TTFT | 请求到达至客户端首次观察到有效 token 的耗时，包含排队、恢复、准入和推理 |

个人工位、请求、文件和用量按租户身份授权；课程对照和全局容量数据由演示者在独立环境查看。账号接入采用部署配置的身份凭据，页面将其映射到当前用户。工位名称和页面元数据由工作台层补齐，授权仍以服务端租户身份为准。

### 状态和异常规则

工作台组合展示三类信息：会话生命周期（如 RUNNING、CHECKPOINTED、SUSPENDED、RESUMING）、模型请求状态和容量回执。RUNNING 会话可以处于模型等待；“等待容量”来自准入或恢复记录。状态映射见[分析模型草稿](MODELING.md#状态图草稿)。

工具执行在服务端确认的当前 epoch 和 OPEN gate 下准入。快照前等待已准入工具完成，恢复时核对 Actor、manifest 与回执水位。快照或恢复结果未知时保留恢复材料，展示需要核对的操作；允许的只读工作区检查以服务端恢复提示为准。

客户端对刷新、重复点击和可重试响应沿用原请求身份与输入。OUTCOME_UNKNOWN 表示结果需核对，原操作进入保守处理流程；已确认的工具结果可直接查询。事件接口遇到保留窗口缺口后，工作台重新读取会话与请求的权威状态。

### 评价与历史证据

资源节省比例为 `(基线资源积分 - 当前资源积分) / 基线资源积分`，基线大于零且配置、负载、测量窗口一致。费用分项依据实际用量、价格与计费单位，缺少物理存储与 I/O 采样时保留状态标记。指标详见[成本口径](../STORAGE_COSTS.md)。

原项目在真实 Substrate MEMORY 与 Dynamo CPU Mocker 环境验证 **64 个有状态 Agent / 4 个 gVisor 热槽位，16× 会话复用**。正式 Gate 2 使用 N32 / N64、每规模五个种子、五种策略，完成 **50/50 trial、14,400/14,400 请求**。相对 TTL15 与 Observed 两种规模达到资源与交互 P95 联合改善；相对 TTL2，N64 交互 P95 更高。系统负载证据与个人用户试用各自保存运行条件和实际样本。

## 三、约束条件

| 编号 | 约束 | 对实现和验收的要求 |
| --- | --- | --- |
| CON-01 | Linux x86_64 或 WSL2 Ubuntu；现有 Go 协调器与 Python 工具链 | 复用仓库版本锁；记录 OS、CPU、内存和依赖版本 |
| CON-02 | 本地演示使用确定性模型和 VOLUMES；真实 MEMORY 采用 Substrate / gVisor | 恢复保真度随演示标识，性能验证使用部署文档的真实环境 |
| CON-03 | 课程策略实验使用受控 Dynamo CPU Mocker | 模型时延与负载固定；资源和交互结论随配置呈现 |
| CON-04 | 单协调器写者、持久日志与身份围栏 | 遵守 advisory lock、revision、epoch、manifest 和回执协议；重启保留未决操作身份 |
| CON-05 | 现有工具单文件及单输出流上限 1 MiB，shell 默认 30 秒、上限 300 秒 | 工作台校验大小并展示受控错误；长任务需求按变更流程评审 |
| CON-06 | 真实共享执行采用隔离沙箱，local-process shell 使用宿主权限 | 本地 shell 只在受信任开发场景显式开启；共享部署用 Substrate。外部监听按现有服务要求配置至少 32 字节凭据及受保护传输 |
| CON-07 | 恢复点默认轮转最近两个已验证 COMMITTED 快照 | 当前 manifest、生命周期和未知结果按协议保护；显示保留策略，资源清理按精确身份执行 |
| CON-08 | 凭据和个人数据按最小公开范围管理 | 服务凭据由服务端配置；公开调研使用匿名编号，保存受访同意范围，个人信息处理遵循适用法律及校方要求 |
