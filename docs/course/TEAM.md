## 共同交付节奏

需求阶段由组长组织学生与个人开发者访谈，产品前端负责人形成原型，调度开发与 DevOps 确认可用接口和运行预算，测试负责人把反馈整理为验收条件。

工作台迭代先完成“创建工位—发起任务—保存现场—恢复后找回文件”的闭环，再完善资源看板和 TTL / v2 对照入口。前端与后端共同确认状态语义，测试通过文件校验、请求回执和运行事件验证展示结果。

算法与实验围绕一个主要问题开展，调度开发主责实现，测试负责人固定配对协议，DevOps 保障环境和清理，产品前端负责人呈现有来源的结果。个人试用与系统负载实验分别保存真实样本和配置。

成员通过 Issue 认领任务，写明需求编号、交付物、负责人和验收条件，并在 PR 中提交成果。每项任务由另一位成员参与验收，评审记录关联对应交付物。实际成员、日期和进度在[选题 Issue](https://github.com/lilong555/agentcloud-course/issues/1)及关联任务中维护。
